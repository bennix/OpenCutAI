# OpenCut AI 功能与可靠性审查

日期：2026-10-03。基于本仓库源码检查，未执行跨平台长时间录屏、真实计费请求或全面许可审计。这里区分已实现、已确认缺口与尚待验证的风险，不把经验推测当成故障事实。

## 优先级与实际缺口

### P0：录屏长期保存在内存，没有崩溃恢复

`apps/web/src/recording/capture.ts` 的 `MediaRecorder.start(1000)` 每秒出块，但块仍追加到 `chunks: Blob[]`，停止后才构造 File。分块回调不等于分块落盘；开启 SmartFocus 会同时录原始视频和聚焦视频，加上系统音频、麦克风，内存持续增长。崩溃后这些块没有恢复入口。

建议：桌面端写临时分块文件及会话清单，写入队列提供背压；录屏结束验证完整性再导入；启动时提供恢复未完成录制。验收：60 分钟多轨录制内存不随文件总量线性增长，强制退出后可恢复已写入部分，磁盘满有明确反馈。Web 版需要独立的持久化与配额策略。

### P0：付费任务恢复还不是完整交易保证

`apps/web/src/ai/editor-adapter.ts` 普通 `/videos` 任务已在 localStorage 保存 ID，`director.ts` 会按项目、场景、分镜 ID 查找现有任务并恢复。失败下载保留任务，素材成功落库后才移除。但仍有这些窗口：

- 提交成功、服务商已计费，响应丢失或应用立即退出：客户端可能还拿不到任务 ID。
- localStorage 保存整个 GenerationInput，其中可有参考图 data URL，可能超过存储配额。
- 同步 `/interactions`、图片调用没有相同的恢复日志。
- 暂停/取消只中断本地请求与轮询，不代表服务商已停止生成或停止计费。
- UI 单窗口 busy 不能替代跨窗口/多调用入口的提交锁或服务端幂等键。

本次修复：普通异步任务收到 ID 后先持久化，再开始轮询；不再先解析缺少素材的排队响应。新增回归测试，确认轮询断网后仍能找到已提交任务。注意：收到 ID 之前的未知提交窗口及存储配额问题仍未解决。

后续：采用有版本的 IndexedDB/桌面任务日志，单独存参考素材；提交前生成 operation ID，按服务商实际能力接入幂等/任务查询。区分「已提交」「提交结果未知」「生成中」「待下载」「待导入」「完成」。结果未知时先对账，不自动重新提交付费请求。

### P1：录屏失败检测有基础，但不覆盖实际内容异常

当前选择系统音频却没有音轨时会报错并释放流；屏幕流结束会触发结束回调。存在权限查询、系统设置入口、单窗口/区域选择、系统音频和麦克风分轨、快捷键、小控制窗、SmartFocus 光标跟随。

缺口：有音轨但持续静音、黑屏、视频尺寸为零、设备切换/轨道 muted、编码器运行途中报错，都没有完整的实时健康状态。编码器错误仅拒绝 stop() 返回的 Promise，缺少立即通知 UI 的通路。浏览器请求 30fps 不等于已经验证了 CFR，多个 Recorder 的同步暂停/恢复也未经过长录制漂移验收。

建议：增加源/编码器健康状态、声音电平与视频首帧预览，异常时保留已录内容并提示。静音或静止画面不应直接判断为失败；先提示用户核验。长录制验证 PTS/音画误差后决定是否转码，不为解决假设问题默认强制全部 CFR 转码。

### P1：缓存容量与资产引用管理不足

生成素材确实下载成 Blob 存在 `opencut-ai-library` IndexedDB；导入项目后还保存项目素材，因而不依赖临时 CDN URL。但存在库和项目双份数据；`listGeneratedAssets()` 用 getAll() 读取全部含 Blob 的记录；仅有逐条「移出 AI 库」，没有总容量、可用空间、批量清理、引用检查或导出备份管理。清站点数据/删除应用数据仍会丢失素材。

建议：元数据分页，Blob 按需取；展示 AI 库/项目/录屏临时文件的占用；清理前区分已被项目引用和孤立素材，提供本地备份。不要按时间自动删除用户作品。先做到内容落库与项目引用事务一致，再考虑去重。

### P1：密钥不是明文，但也不是系统凭据隔离

`apps/web/src/ai/settings.ts` 使用 AES-GCM、随机 IV、不可导出的 CryptoKey，密文和 CryptoKey 均存 IndexedDB；测试验证密文与不可导出属性。设置界面已说明页面脚本仍可使用凭据。渲染进程通过 readApiKey() 解密并在 Authorization 中调用本地 API。没有 macOS Keychain / Windows Credential Manager，也没有主进程独占凭据。

建议：桌面版使用系统安全存储，主进程通过窄接口代发允许的 AI 请求；无安全后端时明确失败/提示，不静默退回明文。Web 版独立说明其边界。`safeStorage` 在 Linux 的实际后端需要检查，不能一概宣称等价于系统钥匙串。

Electron 已设置 nodeIntegration=false、contextIsolation=true、sandbox=true，并限制导航/外部窗口；API 验证 Origin 和允许的路径，媒体代理校验 CDN 域名及重定向。但这些基础不等于完成了 XSS、IPC 和本地 HTTP 攻击面的安全审计。

### P1：生成费用与流控尚无产品化保障

分镜生成按段 await 串行；没有发现预算预估、任务级预算阈值、实际费用账本或统一的 429 Retry-After/指数退避策略。API 服务端有 10 分钟超时，素材下载有 120 秒超时与重试；轮询固定 15 秒、最多 120 次，可取消。普通查询出现临时错误会退出并保留任务，缺少自动恢复退避。

建议：先显示调用次数、镜头数量、总秒数、模型和参考图上传内容。仅在取得可靠的模型价格和计费单位时显示金额；未知价格明确标为未知。客户端预算只能限制新提交，不能追溯停止已计费任务；实际花费以服务商账单/usage 为准。查询和素材下载可以重试，付费 POST 需要幂等能力才可安全重试。

### P2：续接需要质量控制，而不只是末帧提取

`continuity.ts` 已解码上一段，按 `min(分镜时长, 解码时长)-epsilon` 取可见末帧，PNG 输出并限制长边 1920，关闭 sample 并释放 decoder。不是简单截取压缩视频的封面。选择「继续到下一段」和角色参考卡已经存在；Google Omni 不支持参考图的路由会明确拒绝。

缺口：不筛选末帧黑场/模糊、没有选帧预览和替代帧选择；未建立下一段画幅裁切策略。分镜使用连续继承时仍可能漂移，PNG 不消除视频本身已有的压缩损失。建议可视选帧、固定角色/风格参考和重新锚定，而不是强行链式续接所有片段。

## 已有基础，不必重复开发

- **项目版本与迁移**：`services/storage/migrations/index.ts` 当前版本 31，runner 有迁移链。需要补未来版本拒绝/只读、升级前备份与回滚验收，不是从零设计版本号。
- **自动保存**：`core/managers/save-manager.ts` 有 800ms debounce、dirty/flush。自动保存不等于历史快照或录屏崩溃恢复，仍需断电/强退与磁盘满测试。
- **时间精度**：Rust `crates/time/src/media_time.rs` 的核心 MediaTime 为 i64；不能说时间线全用浮点秒。AI/导入边界仍有秒转换，混合帧率与长工程需回归验证。
- **自动化测试**：有 AI 请求、存储、时长、分镜时间线、续接、录屏、快捷键等测试；Rust director 测试覆盖按时长上限拆分并保留角色绑定。缺的是更多真实媒体/长录制/计费故障路径的集成测试，不是完全没有测试。
- **模型目录**：设置有 `/models` 刷新，但只反馈目录数量，并未自动建立按能力/时长/分辨率分类的选择器。仍依赖手工编辑预设模型。
- **角色参考**：分镜支持角色卡和场景首帧生成；不是尚未开始做一致性。下一步应是能力感知和版本对比/回退。
- **音效许可**：搜索仅选择开放许可，并保存来源/作者/许可字段；CC BY/CC BY-SA 仍可能要求署名和其他义务。需要导出素材归属清单，而不是把「开放许可」理解为无需条件。

## 后续功能建议顺序

1. 录屏流式落盘、异常恢复、实时音频/视频健康反馈。
2. 生成任务中心：幂等/状态未知处理、恢复下载、单段版本比较与回退。
3. 空间面板与素材备份；引用安全清理与去重。
4. 生成前确认调用规模、预算和发送参考素材，后续接真实价格/usage。
5. 系统凭据存储、主进程请求隔离、Web/桌面隐私说明分开。
6. 模型能力目录、可视选帧、自定义 API 端点适配；并非改一个 Base URL 就能兼容所有视频路由。
7. 再评估本地 ASR、代理素材、摄像头画中画、自动更新、更多架构安装包等扩展。

未做完整依赖/字体/编码器许可审计，也未发现可据此断言当前打包 GPL ffmpeg 的证据；应从实际安装包依赖清单核验。AI 内容标识要求要结合发行地区、实际用途与适用规定核实，不能仅以一个可选开关宣称合规。
